# サイバー防犯チャレンジ

学園祭の防犯ボランティア・警察署の合同ブースで使う、サイバーセキュリティ啓発用のWebアプリです。
来場者がQRコードから自分のスマートフォンでアクセスし、自分に合ったコースを選んで10問に答えると、判定結果と1問ずつの解説が表示されます。
回答はGoogleスプレッドシートに保存され、ブース運営側で集計に使います。

## コース

| コース | 形式 | 点数 | 判定 |
| :-- | :-- | :-- | :-- |
| 🧒 小学生 | 3択クイズ（A/B/C） | 正解数 | 10点：マスター / 7〜9点：パトロール隊 / 0〜6点：修行中 |
| 🎓 中学生・高校生・大学生 | はい/いいえ | 「はい」の数 | 6〜10個：MAX / 3〜5個：注意 / 0〜2個：安全 |

結果画面の「1問ずつふりかえり」では、次のように表示します。

- 間違えた問題（危険な答えを選んだ問題）：解説と補足情報
- 正解した問題（安全な答えを選んだ問題）：補足情報のみ

## 画面の流れ

```
コース選択 → 質問（1問ずつ） → アンケート（任意） → 結果
```

## 結果画像の保存

結果画面の「📷 結果を画像で保存」から、判定・点数・各問の○×をまとめた画像（認定カード）を保存できます。

- 画像の下のQRコードには、その人の回答を含んだURL（例：`?c=elementary&a=BBACBBBBCB`）が入っています。読み取ると、その人の結果画面と全問の解説が再表示されます。
- 回答はURLに含まれているだけで、サーバーには保存していません。再表示したときは、スプレッドシートへの送信も行いません。
- 画像はブラウザ内で作成します。QRコードの生成には `vendor/qrcode.min.js` を使っています（詳細は `vendor/README.md`）。
- QRコードのURLは、問題の数や選択肢に依存しています。**本番後に問題やコースの `id` を変えると、それ以前に保存された画像のQRコードは、結果を再表示できなくなります**（コース選択画面が開きます）。

## ファイル構成

| ファイル | 内容 |
| :-- | :-- |
| `index.html` | 画面 |
| `style.css` | スタイル（外部ライブラリなし） |
| `questions.js` | **問題セットの定義（問題文・選択肢・解説・判定結果）** |
| `script.js` | 画面の動き・判定・GASへの送信 |
| `Code.gs` | Google Apps Script（回答をスプレッドシートに保存するAPI） |

## 仕組み

```
スマホ（静的ページ） ──POST(JSON)──▶ Google Apps Script ──▶ Googleスプレッドシート
```

- 結果は送信を待たずにブラウザ側ですぐ表示します（会場の通信が遅くても待たせないため）。
- 送信は `mode: 'no-cors'` と `Content-Type: text/plain` で行い、CORSのプリフライトを回避しています。
- 氏名・連絡先など、個人を特定できる情報は取得しません。

## 問題の編集

問題はすべて `questions.js` で管理しています。**問題文・選択肢・解説・判定のしきい値を変えるときは、このファイルだけを編集すれば反映されます**（`script.js` や `Code.gs` を直す必要はありません）。

書き方の詳しい説明は `questions.js` の先頭にあります。主な項目は次のとおりです。

```js
// 3択クイズ（type: "choice"）の問題
{
  title: "パスワード",                 // 見出し（スプレッドシートの列名にもなる）
  text: "一番安全なパスワードはどれ？", // 問題文
  choices: { A: "…", B: "…", C: "…" }, // 選択肢
  answer: "C",                         // 正解
  explanation: "…",                    // 解説（間違えたときに表示）
  tip: "…",                            // 補足情報（いつも表示）
}

// はい/いいえ（type: "yesno"）の問題
{
  category: "詐欺・ネットの罠",
  title: "偽の不在通知SMS",
  text: "…",
  danger: "はい",                      // 危険な答え
  explanation: "…",
  tip: "…",
}
```

結果画面の一番下に参考リンクを出す場合は、セットに `links` を書きます（今は小学生向けのみ）。

```js
linksTitle: "📚 もっと学ぼう！",
links: [
  { title: "ページ名", url: "https://…", note: "一言説明" },
],
```

### 注意

- **本番中に問題の数・順番・見出し（`title`）を変えないでください。** 変えた場合、スプレッドシートの列がずれないように、データは自動で「回答_小学生_2」のような新しいシートに保存されます。
- コースを追加するときは、`questions.js` の `QUIZ_SETS` にセットを追加し、`Code.gs` の `ALLOWED_SHEETS` にそのシート名を追記して、GASを再デプロイしてください。

## セットアップ

### 1. スプレッドシートとGASの準備

1. Googleスプレッドシートを新規作成する。
2. 「拡張機能 > Apps Script」を開き、`Code.gs` の内容を貼り付けて保存する。
3. エディタで `testDoPost` を選んで実行し、権限を許可する。「動作テスト_小学生」「動作テスト_中高大学生」シートにテスト行が追加されれば成功（確認後はシートごと削除してかまいません）。
4. 「デプロイ > 新しいデプロイ」で種類を「ウェブアプリ」にし、次のように設定してデプロイする。
   - 次のユーザーとして実行：自分
   - アクセスできるユーザー：全員
5. 発行されたURL（`https://script.google.com/macros/s/.../exec`）を控える。

> `Code.gs` を修正したときは「デプロイを管理 > 編集（鉛筆アイコン） > バージョン：新バージョン」で更新すると、URLを変えずに反映できます。

> 初回実行時に「このアプリは Google で確認されていません」と表示された場合は、「詳細」→「（プロジェクト名）（安全ではないページ）に移動」→「許可」と進んでください。

### 2. フロントエンドの設定

`script.js` 冒頭の `GAS_ENDPOINT` に、控えたURLを設定します。

```js
const GAS_ENDPOINT = 'https://script.google.com/macros/s/xxxxxxxx/exec';
```

空のままでも診断は動きますが、データは送信されません。

### 3. 公開

`index.html` / `style.css` / `questions.js` / `script.js` と `images/`・`vendor/` フォルダを、HTTPSで配信できる静的ホスティング（GitHub Pages、Cloudflare Pages、Vercel など）に置きます。

GitHub Pagesの場合：リポジトリの「Settings > Pages」で、Source を「Deploy from a branch」、ブランチを `main`・フォルダを `/ (root)` にします。

公開URLからQRコードを作成し、ブースに掲示します。

## ローカルでの確認

`index.html` をブラウザで直接開けば動作を確認できます。

## スプレッドシート

コースごとにシートが自動で作られます（「回答_小学生」「回答_中高大学生」）。1行目の見出しは、送られてきた問題に合わせて自動で作られます。

| 列 | 項目 |
| :-- | :-- |
| A | タイムスタンプ |
| B〜K | Q1〜Q10の回答（小学生：`C○` `A×` のように「選んだ記号＋正誤」、中高大学生：`はい` / `いいえ`） |
| L | 点数（小学生：正解数、中高大学生：はいの数） |
| M | 判定 |
| N | 年齢層 |
| O | 感想_選択（「, 」区切り） |
| P | 感想_自由記述 |
